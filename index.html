💡 纯前端接口调用与严格判定原理

1. 视觉能力 (Vision) 防误判机制

向模型发送包含真值红色背景色块的真实 PNG 图片。不仅检测是否 HTTP 200，还会过滤拒答黑名单（如“无法查看图片”、“纯文本模型”等），且必须准确识别出目标颜色。若中转站吞了图片仅发文字导致模型回答“看不到图”，系统将坚决标为不支持。

误判防护：颜色词按单词边界匹配（避免 credits、hundred 里的 red 造成假通过）；正文若命中欠费/限流/鉴权等上游错误提示（如 enough credits、top up、rate limit、余额不足、额度不足），即使包含颜色词也判为不支持。

2. 工具调用 (Tools / Function Calling) 严格结构验证

传入 get_current_weather 函数定义。必须同时满足：① 返回标准 tool_calls 数组；② 函数名准确命中；③ 参数可解析为合法 JSON 且提取出 location="Tokyo" 参数。可在详情中直接查阅完整的调用 JSON。

3. 深度思考输出 (Thinking / Reasoning) 检测

全兼容 OpenAI 接口与各大推理模型规范。请求始终显式携带 stream 字段（默认 false），可在左侧开启流式（true），开启后按 SSE 增量还原完整思考链；并显式携带 reasoning_effort（可在左侧选择 high / medium / low，默认 high）。自动解析 reasoning_content、reasoning、thought 以及正文内嵌的 <think>...</think> 思考标签，严谨统计思考字数与耗时，剥离思考链让正文不受污染并以折叠卡片形式美观展示。

通用防误判：各维度都会检查响应正文是否属于上层错误提示（欠费、限流、鉴权失败、模型不存在等）。这类 HTTP 200 的“伪成功”一律判为不支持，不会因为正文里恰好含有 red、get_current_weather 等关键词而误通过。

思考判定标准（严格）：上述字段为 null、空串或纯空白时一律视为“未返回思考文本”，不算支持；usage 报告了 reasoning_tokens 但思考文本为空，同样判为不支持（仅有计数无法验证思考链）。只有在没有独立思考字段、但正文确实包含明确分步推理结构（如 “Step 1 / 第一步 / 逐步分析” 且篇幅足够）时，才按“正文推理”计入支持。

4. 鹈鹕骑单车 (Pelican on a Bicycle) 动画基准测试

基于开源大模型社区广泛采用的经典测试题：生成一个svg动画：鹈鹕骑自行车，用H5给我展示下。全方位检验模型对于复杂几何空间构图、SVG 矢量元素布局（大嘴咽囊、自行车轮、齿轮踏板）以及 CSS/SVG 关键帧动画的综合代码生成能力，并集成纯前端沙箱实时渲染。该维度不限制 max_tokens，避免代码被截断导致误判为“未生成有效动画”。

5. 请求参数与流式返回

所有检测请求只发送核心参数（model、messages，按维度补充 stream（可选）、 tools、reasoning_effort 或 max_tokens），不发送 temperature、top_p 等采样参数，避免中转站改写或丢弃参数造成干扰。开启流式后接口返回 SSE 时按 data: 增量还原完整内容后再判定；若中转站忽略 stream 直接返回 JSON，也能正常解析。

6. 并发调度

检测任务按「模型 × 检测维度」拆分后进入任务池，由「并发请求数」控制同时在飞的请求数（默认 1，即完全串行）。设为 5 时：检测单个模型，它的 5 个维度会同时发起；检测多个模型时，则最多 5 个请求同时进行，某个请求完成后立即领取下一个任务，模型之间也随之交替推进。实时面板按模型分卡片展示每个维度的进度，可在检测过程中点开查看已完成步骤的报文。

7. 多选模型与批量自动化

支持多选任意模型或全选当前搜索过滤的模型，一键开启多模型批量检测，带任务进度展示与实时步骤跟踪。
